# Data Analyst Interview Preparation — Phase 2

## Overview

A 10-day Data Analyst interview-preparation system built around a consolidated interview-question bank from 7 PDFs.

- ~285 unique questions after deduplication
- Power BI excluded
- Tableau retained as the BI / visualization tool
- SQL is the primary technical focus
- Excel is practiced daily
- Job applications continue every night
- Goal: interview readiness through solving, explaining, and defending answers—not memorization

---

## Daily Schedule

### 🌅 Morning — SQL War Room

**1. 5 Monster Queries**

Continue the existing 5 Monster Query practice covering complex joins, CTEs, window functions, subqueries, aggregations, business logic, ranking, optimization, and real-world analytical problems.

**2. 15 SQL Interview Questions**

Practice 15 questions from the consolidated SQL interview bank.

For each question:

1. Attempt independently.
2. Explain the approach.
3. Write SQL when required.
4. Receive evaluation.
5. Fix gaps.
6. Handle follow-up questions.

**Morning target: 20 SQL problems/questions.**

# 10-Day Objective

The target is to work through the entire ~285-question interview universe within 10 days while maintaining continuous SQL and Excel practice.

The objective is:

> **Understand → Reason → Solve → Explain → Defend**

A correct first answer is not necessarily the end of a question. Follow-ups may introduce NULLs, duplicates, ties, large datasets, missing records, performance constraints, or changed business requirements.

# Daily Execution Rules

## Rule 1 — Attempt Before Seeing the Answer

First produce:

- Approach
- Reasoning
- SQL / code / formula where applicable
- Final answer

## Rule 2 — Explain, Don't Recite

Technical answers should follow:

```text
Concept
→ Explanation
→ Example
→ Practical use case
```

SQL answers should follow:

```text
Understand requirement
→ Identify tables
→ Identify relationships
→ Build query
→ Validate result
→ Explain edge cases / performance
```

## Rule 3 — Follow-Ups Matter

A correct first answer can be followed by:

- NULL handling
- Duplicates
- Ties
- Large datasets
- Missing records
- Performance constraints
- Changed business requirements
- Alternative approaches

## Rule 4 — Track Weak Areas

Classify mistakes as:

```text
Concept Gap
Syntax Error
Logic Error
Misread Requirement
Communication Problem
Edge Case Missed
Performance Problem
```

Weak areas become priority revision topics.
